# Inkwild (working title)

Status: ready-for-agent

The Skill list ([docs/curriculum/skill-list.md](../../docs/curriculum/skill-list.md)) was signed off by the teacher on 2026-11-05.

## Problem Statement

A Grade 5/6 composite class at Diamond Creek East PS spans about three years of reading and writing ability. It runs from roughly 18 months below the start of Level 5 to 18 months above the end of Level 6. When students finish class work early, they choose between silent reading and something else. Nothing on their iPads gives them reading and writing practice that is pitched to their own level, that they would choose for fun, and that needs no work from staff. The school's OG program already covers word work (spelling, phonics, morphology). The gap is sentence-level and text-level reading and writing in the Victorian Curriculum v2.0.

## Solution

Inkwild is a creature-collecting adventure across an archipelago. It runs in Safari on each Student's own iPad and is added to the Home Screen. Each of nine Islands is one Branch of the curriculum. Students sail between Islands, befriend original Creatures by doing that Branch's Skills in Encounters, evolve them by mastering Skills, battle Keepers for badges, and read a year-long story, MAXX OUT, in Chapters written at their own Band.

Difficulty adapts silently per Branch across four Bands (Levels 4, 5, 6, 7). Every Skill is taught inside the game before it is tested (Teach sequence). Every wrong move gets a one-line reason and another try (Second look). Nothing is ever lost. There is no AI, no server, no account and no teacher dashboard. Progress lives on the iPad and is protected by a weekly 12-character Backup code the Student copies into their book. It is a free static web app on GitHub Pages.

## User Stories

### Getting in

1. As a Student, I want to tap the Home Screen icon and be playing within 10 seconds, so that a few spare minutes in class are worth using.
2. As a Student, I want one big Continue button that drops me back where I was, or into today's Tide quest, so that I never wade through menus.
3. As a Student, I want the game to work with no internet once it has loaded, so that patchy school Wi-Fi never stops me.
4. As a Student opening the game for the first time, I want to create my captain from hair, skin, clothes and colours with no "boy" or "girl" default, so that the captain looks like me.
5. As a Student opening the game for the first time, I want to pick three things I'm into from a list of topics, so that the texts I read are about things I care about.
6. As a Student, I want to change my interests later, so that the game keeps up with me.
7. As a teacher, I want a one-page setup sheet showing how to Add to Home Screen, so that I can set the class up in one session.
8. As a Student who opens the game in a Safari tab rather than from the Home Screen, I want a friendly prompt showing me how to add it, so that my Save isn't deleted after a week away.
9. As a Student, I want every sitting to save automatically after every Encounter, so that I can stop at any moment and lose nothing.

### The world

10. As a Student, I want a living home Island (water, foam, swaying trees, birds, a crab, my hut and my boat), so that the game feels like a real current game and not an educational app.
11. As a Student, I want to sail my boat to any of the nine Islands from day one, so that I choose where I go.
12. As a Student, I want each Island to look and feel different (reef, red rock, mangroves, volcanic, alpine and more), so that every trip feels new.
13. As a Student, I want my home Island to grow with things I unlock across every Branch, so that I can see how far I've come.
14. As a Student, I want to dress my boat, captain and home Island with cosmetics I've unlocked, so that my game is mine.
15. As a Student, I want a crew of distinct characters (a footy-mad navigator, a gross-science engineer, a gamer, an animal rescuer, an artist, a joker), so that someone in the crew is like me.
16. As a Student, I want the game to be funny, so that I keep reading.

### Encounters and learning

17. As a Student, I want each Encounter to be something happening in the world (a Creature tangled in a sentence, a claim to block, tracks to read), so that it never feels like a quiz.
18. As a Student, I want an Encounter to take 2 to 4 minutes, so that I can finish one in a short gap.
19. As a Student meeting a new Skill, I want a crew member to show me the move once, then help me try it twice, before I ever do it alone, so that I'm never tested on something I haven't been taught.
20. As a Student, I want every Skill to tell me in one line why it matters and how to use it in my own writing, so that I know what it's for.
21. As a Student who chooses a wrong option, I want a one-line reason that explains why that option is wrong, then another try with nothing lost, so that a mistake becomes a second look and not a failure.
22. As a Student who is wrong twice, I want the game to show me the answer with its reason as a worked example, so that I'm never stuck.
23. As a Student who keeps needing Second looks on one Skill, I want to be offered a quick replay of the crew member's demonstration, so that I can re-learn it.
24. As a Student, I want to tap any word in a text to hear it spoken, so that one hard word doesn't stop me reading.
25. As a Student, I want the game never to read whole passages aloud, so that I'm the one doing the reading.
26. As a Student, I want to answer by tapping chips, tapping words in the text, dragging tiles into order or building sentences from tiles, so that answering is quick on a touchscreen.
27. As a Student, I want the texts I read to be about my interests more often, so that I want to read them.
28. As a Student, I want to rarely see the same Encounter twice, so that it never gets repetitive.
29. As a Student, I want the work to feel about right for me (not babyish, not impossible), so that I keep choosing it.
30. As a Student, I want there to be no levels, grades or labels anywhere, so that nobody can tell who's "on the easy stuff".
31. As a Student who is ahead, I want harder texts and trickier options without being told I've "levelled up", so that I'm stretched without it being a status thing.
32. As a Student who is behind, I want shorter texts, plainer words and more support on the same Skill as everyone else, so that I'm doing the same thing as my friends.
33. As a Student who is strong at inference but weak at punctuation, I want each Branch to adapt on its own, so that each part of the game fits me.

### Creatures

34. As a Student, I want to befriend a Creature by doing the Skill it's tied to, so that collecting and learning are the same thing.
35. As a Student, I want my Creatures to gain XP and levels as I use their Skill, so that practice feels like progress.
36. As a Student, I want a Creature to evolve, with a big animated moment, when I master its Skill, so that mastery feels like an event.
37. As a Student, I want rare and shiny Creatures to turn up now and then, so that there's always a chance of something special.
38. As a Student, I want a Field Guide showing every Creature I've met or befriended, with empty slots for the rest, so that I want to fill it.
39. As a Student, I want some Creatures to live only on certain Islands, so that I have reasons to explore and talk to friends.

### Swaps

40. As a Student, I want to swap a Creature with a friend face to face, by one iPad showing a QR code and the other scanning it, so that we can share with no internet.
41. As a Student, I want a Swap to give my friend a copy while I keep mine, so that nobody can be talked out of a rare Creature at lunch.
42. As a Student, I want received Creatures to be marked as from a Swap in my Field Guide, so that I know where they came from.

### Keepers, badges and Heists

43. As a Student, I want to battle an Island's Keeper in turn-based fights where every move is a reading or writing act, so that getting good matters.
44. As a Student, I want a right answer first time to land a big hit with screen shake and particles, so that it feels powerful.
45. As a Student who loses a Keeper battle, I want to simply retreat and try again later with every Creature still mine, so that losing costs nothing.
46. As a Student, I want a badge for beating each Keeper, so that I have nine goals to chase.
47. As a Student, I want beating a Keeper to open the far side of the Island with its harder Skills, so that the badge unlocks something new.
48. As a Student, I want each Island's story to end in a Heist on one of Maxx's bases, so that I break Creatures out and collect evidence.

### The story

49. As a Student, I want a year-long story, MAXX OUT, about a lying mega-streamer secretly capturing rare Creatures, so that I want to know what happens next.
50. As a Student, I want new Chapters to unlock as I progress, so that reading the story is the reward.
51. As a Student, I want every Chapter written at my Band, so that I read the same plot as my friends at a level I can manage.
52. As a Student, I want twists (a crew member is Maxx's little sister, his robot butler changes sides, a rival streamer teams up and double-crosses us), so that the story surprises me.
53. As a Student, I want the finale to be hijacking Maxx's live stream and proving his lies, so that the persuasion and bias I've learnt pay off.
54. As a Student, I want to reread any Chapter I've unlocked, so that I can catch up or enjoy it again.

### Story workshop

55. As a Student, I want a Story workshop where I write my own Pieces after a short mentor-text lesson, so that I write about what I want.
56. As a Student, I want my Pieces never to be marked, so that I can write freely.
57. As a Student, I want to tick my own checklist for each Piece, so that I check my own writing.
58. As a Student, I want a Show my teacher button that displays my Piece full-screen in large text, so that I can walk it over and show it off.
59. As a Student, I want my Pieces kept only on my iPad, so that nobody sees them unless I choose to show them.

### Motivation without pressure

60. As a Student, I want a daily Tide quest pointing me at a Branch I've neglected, with a bonus (extra XP and a better shiny chance), so that I have a reason to try somewhere new.
61. As a Student, I want a streak that pauses when I miss a day and never resets, so that a weekend never wipes it.
62. As a Student, I want no energy system and no daily time limit, so that I can keep playing as long as I like.
63. As a Student, I want no leaderboards and no percentage scores, so that I'm never ranked against my classmates.
64. As a Student, I want a progress page showing my Creatures, badges and Skills mastered, so that I can choose to show my teacher what I've done.

### Saves and backups

65. As a Student, I want the game to ask me once a week to copy a 12-character Backup code into my book, so that my progress can be restored if my iPad is wiped.
66. As a Student, I want to prove I copied it by typing it back from my book, and to try again until it matches, so that my book copy is always right.
67. As a Student who mis-copies one character, I want the game to tell me straight away that the code is wrong, so that a bad code never gets into my book.
68. As a Student, I want codes without look-alike characters (no O/0, I/1/L, S/5), so that I can read my own handwriting.
69. As a Student on a new or reset iPad, I want to type my Backup code and get my badges, Skills, Bands, Creatures and Chapters back, so that a wiped iPad isn't the end.
70. As a Student who wants everything backed up, including swapped and shiny Creatures and my Pieces, I want an optional Save to Files, so that I can restore all of it.

### Reading comfort and sound

71. As a Student, I want three text sizes, so that I can read comfortably.
72. As a dyslexic Student, I want extra letter and line spacing and a soft cream background behind reading text, so that the words don't swim.
73. As a Student, I want reading text in a clean, plain font and the pixel font only for headings and buttons, so that the game's look never makes reading harder.
74. As a Student in class, I want the game silent by default, so that I don't disturb anyone.
75. As a Student with headphones, I want to turn on music and sound effects, so that the game feels fuller.

### Teacher

76. As a teacher, I want no dashboard, no setup and no data to manage, so that the game adds no work.
77. As a teacher, I want every Skill traced to Victorian Curriculum codes, so that I can explain what the game covers.
78. As a teacher, I want to spot-check 10 Encounters per Island chosen from the ones the checks were least sure about, so that my limited checking time goes where it matters.
79. As a teacher, I want a short note explaining that First Nations literature is taught in class and not in the game, so that the gap is clearly deliberate.
80. As a teacher, I want the game's name changeable in one place, so that the class can vote on the real name.

## Implementation Decisions

### Platform

- A static web app in TypeScript, built with Vite into plain files and hosted on GitHub Pages from the teacher's own public repository, licensed CC BY 4.0 (check with the principal first).
- It is a progressive web app with a manifest, Home Screen icon and service worker. The service worker caches every asset, so the game runs offline after the first visit and updates itself on the next online launch.
- The target is Safari on iPadOS 16 and later, in both orientations, from 768×1024 CSS pixels up. The layout is touch-only, with hit targets of at least 44 points.
- There are no runtime dependencies except a small QR encoder and decoder for Swaps.
- The game's title lives in one config value.

### Data shapes (foundational)

- **Content bank.** Content is read-only data validated against a schema at build time. It holds:
  - Branches, in order.
  - Skills, each with Branch, order, curriculum codes, student-facing name, WHY line, HOW line and Teach sequence.
  - Encounters, each with Skill, Band, format, topic, text, prompt, answer and a reason for every wrong option.
  - Chapters at four Bands.
  - Creatures, each tied to a Skill, with base and evolved forms.
  - Keepers, cosmetics, crew and interests.

  Encounters and Chapters are authored as data files, not code.
- **Encounter formats** are a closed set, each with its own answer shape and checker:
  - *choose*: tap one chip.
  - *tap-text*: tap the word or span in the text.
  - *order*: drag tiles into sequence.
  - *build*: assemble a sentence from tiles. The answer is a set of accepted tile sequences.
  - *fix*: tap the faulty spot, then choose the correction.
  - *sort*: drag items into two or three bins.

  The Story workshop has its own free-typing surface, which is never checked.
- **Save.** The Student's whole state, owned by the game core. It holds:
  - The Band per Branch.
  - Per Skill: taught or not, recent results and mastered or not.
  - Route position per Branch.
  - Keeper badges and Chapters read.
  - Received and shiny Creatures.
  - Pieces.
  - Interests, captain look and chosen cosmetics.
  - Settings, streak state and Tide quest state.
  - Encounters seen per pool, so they don't repeat.

  Befriended Creatures, Creature levels and evolutions, and unlocked cosmetics are *derived* from progress, never stored. That is what keeps the Backup code short.
- **Route.** Each Island is a fixed linear route: Skills up to the midpoint, then the Keeper, then the remaining Skills. The route position counts mastered Skills plus the Keeper, in route order. Completing the route unlocks the Heist Chapter, so the Heist needs no stored state of its own. A Skill unlocks once the Skill before it has finished its Teach sequence and three Encounters. The Keeper unlocks once every Skill before it is mastered. The far side of the Island unlocks after the badge.

### Game core (the main seam)

- A pure module: given the content bank, a Save and a Student action, it returns the next Save and an outcome for the UI to show (Second look reason, Creature befriended, evolution, Band change in silence, Chapter unlocked). It holds every rule: routing, adaptivity, mastery, Creatures, Keeper battles, Tide quest, streak and backup reminders.
- It has no DOM, no storage and no clock of its own. The current date and a random seed are passed in, so every rule is testable and replayable.
- The UI is a thin view over the core. Persistence wraps it.

### Adaptivity (Bands)

- Every Branch starts at Band 2 (Level 5).
- **Placement** covers the first six Encounters in a Branch. Two first-try successes in a row move the Band up. Two Encounters in a row needing a Second look move it down.
- **After placement**, the Band moves up after 5 of the last 6 Encounters in that Branch are right first try. It moves down after 3 of the last 6 need two Second looks. The gap between the two keeps Bands stable.
- Band changes are never shown or announced. A Band drop never removes mastery.

### Mastery

- A Skill is mastered when 4 of its last 5 Encounters are right first try at the Student's current Band for that Branch, across at least two different days. Spacing them out stops cramming.
- Mastering a Skill evolves its Creature.
- Story workshop Skills are "mastered" when the Student finishes a Piece for that prompt and ticks their own checklist.

### Teach sequence and Second look

- **I do**: a crew member works one example aloud in text, with the WHY and HOW lines.
- **We do**: two items with the hint shown before the Student answers.
- **You do**: ordinary Encounters.
- The Teach sequence is written once per Skill in plain Level 4 to 5 language.
- **Second look**: every wrong option carries its own one-line reason. After two wrong tries, the answer is shown with its reason and the Encounter counts as not first try.
- Three Encounters of one Skill in a row needing a Second look offer a replay of the I do.

### Encounter selection

- The next Encounter for a Skill is drawn from that Skill and Band's pool, skipping any already seen until the pool is used up.
- Topics matching the Student's interests are weighted three to one.
- Island play mixes the newest unlocked Skill with spaced review of earlier ones.

### Keeper battles

- Five to seven turns. Each turn is an Encounter drawn from the near side of that Island's Skills at the Student's Band, framed as a move.
- Right first try lands a full hit. Right after a Second look lands a half hit. A miss lets the Keeper land a chip hit.
- Losing means retreating. Nothing is lost, and the Keeper can be fought again at once.
- The Story workshop has no Keeper. Its badge comes from finishing Pieces on every prompt.

### Creatures

- There is one Creature line per Skill, each with a base form and an evolved form, plus one rare Creature per Island earned in its Heist.
- Shiny variants are palette swaps, rolled at befriending: a 1 in 64 chance, or 1 in 16 on a Tide quest.
- All art is pixel art drawn in code, using the outline sprite method from the visual sample, in the style signed off in the island sample.
- Swaps send a Creature id plus a shiny flag in a QR code. The receiver gets a copy marked as received. No nicknames or free text travel.

### Backup code

- 12 characters in three groups of four, from a 29-symbol alphabet with O, 0, I, 1, L, S and 5 removed. Eleven characters carry data and one is a weighted check character mod 29. Because 29 is prime, the check catches every single wrong character and every swap of two neighbouring characters.
- The payload is a mixed-radix number:
  - a 4-bit format version
  - each marked Branch's route position (0 to its route length) and Band (1 to 4)
  - the Story workshop's count of prompts finished

  With the current Skill list this is 48.6 bits plus the version, 52.6 in all, against the 53.4 bits that 11 characters hold. Adding Skills later means taking a version bit or retiring an old format.
- Not restored from a code:
  - Swapped and shiny Creatures, and Pieces (only Save to Files restores these).
  - Interests and captain look (re-picked in under a minute on restore).
  - Mastery out of route order (re-earned quickly, because the Band is restored).
- **Weekly flow:**
  1. The game shows the code.
  2. The Student taps "I've copied it" and the code is hidden.
  3. The Student types it back from their book.
  4. If it doesn't match, the game shows the code again for the Student to fix the book copy, then hides it and asks again, until it matches.
- **Save to Files** writes the whole Save as a file through the iPad share sheet and restores it from Files.

### Persistence

- The Save is written to local storage after every Encounter. On launch, the game asks the browser to keep its storage persistent.
- When the game is not running from the Home Screen, it shows the Add to Home Screen prompt, because Safari deletes site data for websites not on the Home Screen after 7 days without a visit.

### Rendering

- The world, Creatures, sailing and battles are drawn on a canvas at a low logical resolution and scaled up with crisp pixels. Water, foam, swaying trees, cloud shadows, small wildlife, depth sorting, lighting and vignette are as in the island sample.
- All reading text, chips and the heads-up display are HTML over the canvas. Text then stays crisp, tap-to-hear works on every word, and the reading comfort settings apply.
- Reading text uses the system font. The pixel font is only for headings and buttons.
- Tap-to-hear uses the iPad's built-in speech, with an Australian English voice where one exists, and works even when sound is off.

### Content pipeline (build time, AI allowed while building)

- Content is written by Claude to the Skill list.
- **Rule checks**, which fail the build:
  - the schema is valid
  - there is exactly one correct option
  - the answer appears in the text where the format needs it
  - every wrong option has a reason
  - spelling is Australian
  - no word work leaks in
- **Band checks** against these targets:

  | Band | Average sentence length | Passage length |
  |---|---|---|
  | 1 | 12 words or fewer | 60 to 120 words |
  | 2 | 15 words or fewer | 100 to 180 words |
  | 3 | 18 words or fewer | 150 to 250 words |
  | 4 | 22 words or fewer | 200 to 350 words |

  Each Band also has a target share of words outside a common-word list.
- **Blind solve**: a separate agent answers every Encounter without the key. Any disagreement, or any second defensible answer, flags the Encounter for a rewrite.
- **Spot-check pack**: an "uncertainty" score ranks each Island's Encounters, and the 10 least certain go into a printable spot-check sheet for the teacher.
- Each Island's content must pass the rule checks and the blind solve before it ships.

## Testing Decisions

- **A good test** drives the game core through its public interface, the same way the UI does. It starts a Save, performs Student actions with chosen answers, then asserts what the Student would see: an outcome, a Band, a badge, a Creature, a Chapter. Tests never reach into private state, so the rules can be restructured without rewriting tests.
- **Game core tests cover:**
  - route unlocking
  - Teach-before-test
  - Second look and worked answer
  - Band placement and movement, including hysteresis
  - mastery with the two-day spacing
  - derived Creatures and evolutions
  - Keeper battle outcomes and retreat
  - Tide quest choice of neglected Branch
  - streak pausing across missed days
  - weekly backup reminder timing
- **Backup code tests** are property tests: every reachable Save survives a round trip with its restorable parts intact, and every single-character error and every neighbouring swap is rejected.
- **Content tests** run the rule checks and Band checks over the whole content bank as part of the test run, so bad content fails like failing code.
- **UI checks**: each milestone is driven in the browser at iPad sizes (768×1024 and 820×1180, both orientations) with touch emulation. Then the teacher tests on a real school iPad at three milestones: first Island playable, half the Islands, full game. This also checks the department web filter.
- There is no prior art. This is a new repository.

## Out of Scope

- Word work: spelling, phonics, morphology, handwriting (ADR 0002).
- Speaking and listening.
- Visual texts (VC2E5LA07, VC2E6LA07).
- First Nations stories (ADR 0003).
- Colons and semicolons.
- AI of any kind inside the game, and any server (ADR 0001).
- Accounts, logins, profiles and shared-iPad support.
- A teacher dashboard and any data leaving the iPad.
- Leaderboards, percentage scores, energy and time caps.
- Teacher-set weekly focus.
- Creature nicknames.
- Online multiplayer.
- Student-designed Creatures (a later update).
- Exporting or emailing Pieces.
